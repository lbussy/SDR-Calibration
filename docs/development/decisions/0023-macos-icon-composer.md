# Use one Icon Composer source for macOS icon generations

## Context

macOS 26 places irregular legacy icons on a gray fallback enclosure. The
existing ICNS correctly removed its historical black matte but still presented
an irregular transparent silhouette to the new icon system.

## Decision

The macOS application uses the project-owned
`assets/icons/macos/SDRCalibration.icon` document as its authoritative Apple
icon source. During the CMake build, Xcode `actool` compiles the document for
the macOS 14.0 deployment target. The bundle receives `Assets.car` for the
current macOS icon system and the ICNS rendition generated by the same
compilation for supported earlier releases.

The Icon Composer layer is an opaque 1024-pixel square derived
deterministically from the approved raster master. A blue enclosure extends to
the square canvas so macOS can apply its own rounded mask without supplying a
gray fallback background.

## Consequences

- The macOS 26 and pre-26 renditions share one editable Apple icon document.
- The generated pre-26 appearance can differ from the earlier project-generated
  ICNS and requires separate visual qualification.
- Building the macOS GUI requires an installed Xcode toolchain with `actool`.
- Windows ICO and Linux hicolor generation remain based on the original raster
  masters and are unchanged.
- `Assets.car`, generated ICNS, bundle metadata, signing order, and actual OS
  selection remain package-level validation responsibilities.
